Browser → FNOL backend

User submits the claim form in the React SPA. The frontend POSTs to http://localhost:8001/fnol/submit with Authorization: Bearer <jwt> and X-Source: prod (explicitly set by the SPA's fetch wrapper per ADR-011 amendment).

2

FNOL request-logger middleware (inbound)

The middleware reads X-Source and binds it onto structlog.contextvars so every domain event during the request inherits the source. It emits an event=request line with caller, user, method, path, status, duration_ms, source — never the token or password.

apps/fnol/src/fnol/middleware/request_logger.py ADR-011
↓
3

FNOL → Shared Data API

Handler builds the SDA POST /claims with X-API-Key: $SHARED_DATA_API_KEY_FNOL (inter-service), forwarded Authorization: Bearer <user-jwt>, and X-Source read from the contextvar. SDA enforces jwt.app == "fnol" defense-in-depth (per ADR-006), inserts the claim into Postgres, and logs its own request line. Non-2xx from SDA → FNOL logs sda_upstream_rejected (WARN) with detail parsed from the response body, never from response headers (which could echo Authorization / X-API-Key).

4

structlog → two sinks

FNOL's logger fans out every record to two handlers configured in logging_setup.py:

  • stdout — visible via docker compose logs fnol-app
  • RotatingFileHandler — /app/logs/fnol-app.log (10 MB cap, 5 backups)

Both emit identical JSON lines. Exception tracebacks land on the same handlers as multi-line text.

apps/fnol/src/fnol/logging_setup.py cache_logger_on_first_use=False

Docker volume — fnol-logs

The FNOL service mounts fnol-logs:/app/logs. Writes to /app/logs/fnol-app.log inside the container land on the named volume — survive restarts, live in Docker's volume store.

Dashboard mounts the same volume — read-only

The log-dashboard service mounts fnol-logs:/mnt/logs/fnol:ro. The same bytes FNOL wrote are visible at /mnt/logs/fnol/fnol-app.log inside the dashboard container — the :ro is enforced by the kernel.

UI rendering

8b

Parser + source inference

The FNOL structlog parser converts each line to a LogEntry. _infer_source precedence:

  1. event=request and path ∈ healthcheck paths → "health"
  2. Explicit source=<value> in the line → that value
  3. Otherwise → "unknown"

Step 3 is the ADR-011 amendment (2026-06-07): React SPAs explicitly tag prod; anything missing the header lands in unknown as a propagation-gap signal.

ingest/parsers.py:_infer_source ADR-011 amendment
↓
9

3-knob ingest gate (two seams, both before any embed call)

  • DASHBOARD_INGEST_LEVELS — default DEBUG,INFO,WARN,ERROR (Phase 8 / ADR-017 — full corpus; was WARN,ERROR Phase 7 cost-driven) — checked in filter_for_ingest
  • DASHBOARD_INGEST_SOURCES — default prod,synthetic,unknown — same filter_for_ingest
  • DASHBOARD_INGEST_DRY_RUN — default false — checked on upsert_entries(..., dry_run=...) which short-circuits before any Chroma read or embedding call

Post-Phase-8, every level enters Chroma so the agent has baseline INFO data to anchor against. A successful claim submission (INFO) is now embedded — the agent uses it to learn what "normal" looks like. The source filter still drops Playwright test and parser-derived health traffic (signal-quality, not cost).

10

Dedup → Ollama → Chroma

For surviving entries, upsert_entries queries Chroma for {app}:{sha1(raw)[:16]} IDs (content-hash, single SQL-shape _collection.get(ids=..., include=[])). New ones go to local Ollama nomic-embed-text as a batch — 768-dim vectors (Phase 8 / ADR-017; replaces OpenAI text-embedding-3-small 1536-dim). The vectors land in the dashboard-logs collection in the chroma-data volume. Same line twice = same content hash = single row.

ingest/vectorstore.py collection: dashboard-logs
↓
11

Agent surfaces

Chroma is the corpus for: POST /api/logs/search (semantic search), GET /api/errors/{id} (Error Detail + Suggested Fix), POST /api/chat (AI Chat StateGraph), the proactive scan loop (opt-in), and Vectorstore Stats.

What changed since the original walkthrough
  • Source default flipped from prod to unknown (step 8b) — ADR-011 amendment 2026-06-07 (PR #42). React SPAs now explicitly tag X-Source: prod.
  • Ingest gate sources widened to prod,synthetic,unknown (step 9) — admits Agitator traffic and the propagation-gap signal so the operator can see drift.
  • JWT app-claim defense-in-depth lives in ADR-006, not ADR-007 (which is the background claim-status simulator).
  • The file handler is RotatingFileHandler (10 MB cap, 5 backups), not a plain FileHandler.
